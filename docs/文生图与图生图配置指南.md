# 文生图与图生图配置指南

Cursor 助手把 Cursor 客户端的 GenerateImage 工具接到上游 OpenAI 兼容的 images API：
- **文生图** → `POST {baseURL}/v1/images/generations`
- **图生图** → `POST {baseURL}/v1/images/edits`（multipart，参考图随本轮上传图自动取用）

上游需支持 OpenAI 兼容 images 端点（如 `gpt-image-2`、`dall-e-3` 等）。实测 `gpt-image-2` 文生图约 2-3 分钟、图生图约 1.5 分钟出图，**慢是上游特性、不是 bug**——本程序已把整体超时放到 15 分钟，不砍慢请求。

## 1. 两种配置形态

生图能力可挂在**两种 adapter 形态**上，按「用途 Role」字段区分。在「模型配置」页编辑或新增 adapter，填「用途 (Role)」：

| Role | ModelID | Image 模型 | 适用场景 |
|---|---|---|---|
| `chat` | 必填 | 可空 | 仅聊天，不生图（默认） |
| `image` | 可空（后端兜底成 Image 模型） | 必填 | **独立生图 adapter**，不参与聊天路由，只用图生图/文生图 |
| `both` | 必填 | 必填 | **同一 adapter 既能聊天又能生图**（推荐：一个 endpoint + key 搞定两件事） |

> 前端校验已与后端对齐：`image` 角色允许 ModelID 留空，`both` 角色两者各自必填，`chat` 角色 ModelID 必填。

## 2. 推荐配置：both（一个 adapter 搞定聊天 + 生图）

以 `xc.lifesecretary.com:8000` 为例（chat 模型 `gpt-5.6-terra` + image 模型 `gpt-image-2`）：

| 字段 | 值 |
|---|---|
| 显示名称 | 上游中转 |
| 类型 | openai |
| 用途 (Role) | **both** |
| ModelID | `gpt-5.6-terra`（聊天用） |
| Image 模型 | `gpt-image-2`（生图用） |
| 接口地址 | `https://xc.lifesecretary.com:8000` |
| 访问密钥 | 你的 key |
| OpenAI 端点 | `/v1/responses`（聊天走这个） |

生图时程序自动用同一 adapter 的 baseURL + apiKey + Image 模型打 `/v1/images/generations` 或 `/v1/images/edits`，**无需额外凭据**。

## 3. 独立生图 adapter：image（聊天和生图用不同上游）

若聊天走一个上游、生图走另一个上游（或不想让聊天 adapter 挂生图）：

- **聊天 adapter**：Role=`chat`，只填 ModelID（如 `gpt-5.6-terra`），Image 模型留空。
- **生图 adapter**：Role=`image`，只填 Image 模型（如 `gpt-image-2`）+ 对应 baseURL/apiKey，ModelID 可留空。

生图时 resolveImageChannel 两段兜底：
1. 先按当前 chat 模型找 adapter——命中且挂了 Image 模型或 Role=both/image → 复用；
2. 否则取全局任意 Role=image/both 且 enabled 的 adapter（按 Priority 升序取首个）。

## 4. 在 Cursor 里怎么用

1. 启动 Cursor 助手代理，Cursor 选你配的 chat 模型。
2. **文生图**：直接对话「生成一张少女在海边的图」。agent 调 GenerateImage 工具 → 文生图端点 → 图回传到对话。
3. **图生图**：聊天框**上传一张图** + 文字指令「把背景换成海滩」。上传图随本轮 SelectedImage inline data 到达，程序直取 inline 走 `/v1/images/edits`，**不落盘、不写工作区**（守 F-30）、不依赖模型填对路径。

> 图生图只取**本轮**上传的图。若上游 SSE 中途 reset 导致本轮失败、Cursor 自动重试开新轮，新轮不带图——这时图生图会退化成文生图。正常同轮完成不触发此问题。

## 5. 常见问题排查

看 `~/.cursor-local-assistant-v2/logs/app.log`，搜 `forwarder`：

| 日志行 | 含义 |
|---|---|
| `forwarder image generate ok .../generations... image_bytes=N` | 文生图成功 |
| `forwarder image edit ok .../images/edits... image_bytes=N` | 图生图成功 |
| `forwarder image edit bad_status status=400 body=...MIME type...` | 参考图 Content-Type 不对（已修，若再现报这个请反馈） |
| `forwarder generate image refs resolved mode=generate inline_refs=0` | 没取到参考图，退化成文生图——确认本轮有上传图 |
| `forwarder generate image refs resolved mode=edit inline_refs=1` | 取到参考图，走图生图（正常） |
| `image model is empty` / `image adapter missing baseURL or apiKey` | adapter 配置缺字段，按第 2/3 节补 |
| `openai responses stream: skipping malformed tail payload` | 上游 SSE 残缺，程序已容错跳过、不杀整轮 |

## 6. 安全约束（F-30）

服务端**绝不读** SelectedImage 的 Path 字段、**绝不写工作区文件**做图生图。参考图只从本轮用户上传的 inline data 直取，受 4MB/单图、16MB/总量、6 张上限约束。`loadReferenceImages`（走 `reference_image_paths`）是唯一服务端读工作区文件的场景，仅当模型显式填了工作区路径时才触发。
