# 定价管理黑屏修复全过程（教学复盘）

> 排查时间：2026-07-25
> 故障：首页点「定价管理」→ 窗口纯黑、无法拖动，DevTools 报 `Cannot convert object to primitive value`
> 影响范围：所有进入 `/pricing` 路由的尝试
> 修复产物：`bin/cursor-byok-pricing-test.exe`（MD5 `483f60b5aa40bfaf236549d1c2bbc703`）

这份文档不是“改了什么”，而是“**为什么这么改、怎么一步步定位到的**”。读完你应当能自己复现整条推理链，下次遇到同类黑屏不会再抓瞎。

---

## 0. 现象本身的第一性信息

用户报：
1. 点「定价管理」后**纯黑屏**，啥也不显示
2. 窗口**无法拖动**（`--wails-draggable: drag` 失效或被覆盖）
3. 一次偶然终于看到红色报错：
   ```
   [vue] Cannot convert object to primitive value
   TypeError: Cannot convert object to primitive value
     at String (<anonymous>)
     at z (assets/index-*.js:117:199)
     at Proxy.<anonymous> (...:9633:30)
   ```

**关键观察一**：报错栈顶是 `String(<anonymous>)`，说明是**某处主动 `String(x)` 失败**，而不是渲染逻辑算错数。
**关键观察二**：`9633:30` 这个偏移量稳定出现——指向 bundle 里同一行代码，是 MainLayout 的 header `{{ title }}`。
**关键观察三**：只有 `/pricing` 路由崩，`/`、`/model-config`、`/model-editor` 都正常。这说明路由系统没坏，是**这条路由特有的数据**有毒。

这三个观察合起来已经把范围从“整个 app 坏了”收敛到“`/pricing` 路由的 `meta.title` 让 MainLayout 的 header 插值崩了”。

## 1. 为什么“纯黑”而不是“显示报错”——errorHandler 的吞错 bug

最早我以为没报错。后来用户偶然看到红字，说明报错**一直都在**，只是被吞了。去读 `frontend/src/main.js` 的旧 `app.config.errorHandler`：

```js
// 旧逻辑（简化）
app.config.errorHandler = (err, instance, info) => {
  const root = document.getElementById("root");
  if (root && (!root.children || !root.children.length)) {
    root.innerHTML = `<div style="color:red">${err}</div>`;
  }
};
```

问题在 `!root.children.length` 这个条件——它只在 **root 完全空** 时才写错误。但 Vue 渲染是渐进的：崩在 `{{ title }}` 时，header 的外壳 div、img、一堆兄弟节点**已经渲染了一半**，`root.children.length > 0`，条件不成立 → 错误被默默吞掉 → 用户看到一片黑。

**这是第二层 bug**：不是 errorHandler 没写，是它的触发条件错了。

**修复**：改成无条件写一个**固定在视口、z-index 拉满**的浮层 `#__err_overlay`，再挂 `window.error` 和 `unhandledrejection` 兜底。这样无论 root 处于什么半渲染态，错误都可见、可复制。

```js
function showErrorOverlay(label, err, info) {
  // 直接 createElement + fixed + z-999999，不依赖 #root 状态
  // ...
}
app.config.errorHandler = (err, instance, info) =>
  showErrorOverlay("Vue errorHandler", err, info);
window.addEventListener("error", (e) =>
  showErrorOverlay("window.error", e.error ?? e.message));
window.addEventListener("unhandledrejection", (e) =>
  showErrorOverlay("unhandledrejection", e.reason));
```

> **方法论**：渲染期错误的兜底 UI **不能依赖渲染树状态**。固定定位 + 最高 z-index 的浮层是唯一可靠的“崩溃时仍可见”方案。这一步独立于根因，但没它，根因根本看不见。

## 2. 根因第一层：`staticI18nPlugin` 会递归包装中文串

报错是 `String(x)` 崩，那 `x` 是什么？为什么会是个“转不成原始值”的对象？

### 2.1 插件做了什么

`frontend/plugins/static-i18n-plugin.js` 是一个 Babel 级的**构建期**变换：
- `enforce: "pre"`（在 vite 的其它变换之前跑）
- `transform()` 对每个 `.js/.vue` 源文件，用 `@babel/parser` 解析 AST
- `collectJSReplacements` 里的 `StringLiteral(path)` visitor：**任何含汉字的字符串字面量**，都包成 `localized(hash, source)` 调用
- `hash` = `sha256(原文).slice(0,16)`
- 当 `--scan` 开启时，`syncCatalogFiles` 把这些 hash + 中文写进 `src/i18n/locales/{zh-CN,en-US,ja-JP}.json`

### 2.2 致命的递归点

看 visitor 的判定（简化）：

```js
StringLiteral(path) {
  if (shouldIgnoreStringLiteral(path) || !containsHan(path.node.value)) return;
  // 包成 localized(hash, source)
}
```

它**只看字面量的值有没有汉字，不看这个字面量是不是已经处于一个 `localized()` 调用的参数位**。

于是灾难发生了。我在 `/pricing` 路由写的是：

```js
meta: { title: localized("pricing_panel_title", "成本定价") }
```

插件扫描时，`"成本定价"` **本身就是一个含汉字的 StringLiteral**，于是被二次包装：

```js
// 变换后
meta: { title: localized("pricing_panel_title", localized("82c5adb194b84b77", "成本定价")) }
//                                          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                                          这是个对象，不是字符串！
```

外层 `localized` 的 fallback 参数，从一个原始字符串，变成了一个 **LocalizedText 对象**。

### 2.3 其它路由为什么不崩

`/`、`/model-config` 等路由的 `meta.title` 也都写成了 `localized(hash, "中文")`，也会被二次包装成嵌套对象。但它们**不崩**——因为它们的**外层 hash 是真 locale key**（`--scan` 时写进 JSON 了），`resolveMessage` 第一步就命中，返回字符串，永远走不到 fallback 那个对象。

而 `pricing_panel_title` 是我**手写的伪 key**，locale JSON 里根本没有它 → `resolveMessage` 第一步、第二步都 miss → 返回 fallback → 返回那个嵌套对象 → 崩。

> **方法论**：插件作者的设计隐含一个不变量——“`localized` 的 hash 必须是已登记的真 key”。但没有任何机制强制这条不变量。我手写伪 key 就破坏了它。**构建期变换若不能保证幂等，就会在“看起来无害”的代码上踩雷。**

## 3. 根因第二层：`LocalizedText.toString()` 返回对象

为什么 `String(localizedText对象)` 会抛 `Cannot convert object to primitive value`？看 `frontend/src/i18n/runtime.js`：

```js
class LocalizedText extends String {
  constructor(id, fallback) { super(...); this.id = id; this.fallback = fallback; }
  toString()        { return resolveMessage(this.id, this.fallback); }
  valueOf()         { return resolveMessage(this.id, this.fallback); }
  toJSON()          { return resolveMessage(this.id, this.fallback); }
  get [Symbol.toPrimitive]() {
    return (hint) => resolveMessage(this.id, this.fallback);
  }
}

function resolveMessage(id, fallback) {
  return activeMessages[id] || sourceMessages[id] || fallback || "";
}
```

**致命点**：`Symbol.toPrimitive` 返回的是一个**函数**，函数返回 `resolveMessage(...)` 的结果。当 fallback 是对象时，`resolveMessage` 返回**那个对象**。JS 引擎拿到一个对象作为 `toPrimitive` 的返回值 → 抛 `Cannot convert object to primitive value`。

我用 Node 复现过：

```js
const x = { [Symbol.toPrimitive]: () => ({}) };  // toPrimitive 返回对象
String(x);  // TypeError: Cannot convert object to primitive value  ✓
```

而 Vue 运行时 `toDisplayString`（minified 名 `z`/`x`）内部确实会调 `String(value)` 来把插值结果转成可渲染文本。所以 `{{ title }}` 里那个嵌套 LocalizedText 一进 `toDisplayString` 就炸。

> **方法论**：`extends String` + 自定义 `Symbol.toPrimitive` 是个**地雷组合**。`String` 子类天然会被各处隐式 `String()` 调用，而 `toPrimitive` 一旦可能返回非原始值，就会在完全无关的调用点炸。安全的前提是 `resolveMessage` 的所有分支都返回原始值——这里 `fallback` 是用户传的，没法保证。

## 4. 修复（三处，缺一不可）

### 4.1 路由层：杜绝嵌套
`frontend/src/router/index.js`：

```js
// 改前（嵌套，崩）
{ path: "/pricing", component: PricingPanel,
  meta: { title: localized("pricing_panel_title", "成本定价"), ... } }

// 改后（单层，安全）
{ path: "/pricing", component: PricingPanel,
  meta: { title: "成本定价", ... } }
```

插件仍会把 `"成本定价"` 包成 `localized("82c5adb194b84b77", "成本定价")`——**单层**，fallback 是原始字符串，就算 hash 万一没命中，也只会显示原文而不是崩。

**规则固化**：`meta.title` 只接受原始字符串或单层 `localized(hex, "中文")`，**绝不嵌套**。已在 router 源码加注释。

### 4.2 布局层：插值点兜底
`frontend/src/layouts/MainLayout.vue`：

```js
const title = computed(() => {
  const raw = route.meta.title ?? "Cursor助手";
  try { return String(raw); } catch { return "Cursor助手"; }
});
```

即便将来再混进嵌套对象，`String()` 在 try 里抛 → catch 兜底默认标题，header 不崩。这是**纵深防御**——4.1 修了已知雷，4.2 保证未知雷也不致命。

### 4.3 运行时层：错误可见
`frontend/src/main.js`：无条件 `showErrorOverlay` + 两个全局监听（见 §1）。任何渲染期异常都浮层可见，不再有“黑屏 = 无信息”的盲区。

### 4.4 数据层：locale 写入
跑 `npm run build -- --scan`，把 `"成本定价"` 的 hash `82c5adb194b84b77` 连同原文写进 `src/i18n/locales/zh-CN.json`。这样即使走 `localized("82c5adb194b84b77", "成本定价")`，`resolveMessage` 第一步就命中，返回字符串。

## 5. 构建链的坑：syso 是前端载体

改完前端，**必须重跑两步**才能让 exe 里是真新前端：

1. `wails3 generate syso -arch amd64 ...` —— 把 `frontend/dist/**` 嵌进 `wails_windows_amd64.syso`
2. `go build -tags production ...` —— 把 syso 链进 exe

我中途踩过：`dist/` 已经是 21:48 的新构建，但 `wails_windows_amd64.syso` 还停在 20:42 的旧版。直接 `go build` 出来的 exe 里前端是旧的，白测。判据：**syso 的 mtime 必须晚于 `frontend/dist` 里最新文件**，否则陈旧。

完整三步链见 [接口与架构速查.md](接口与架构速查.md) §八。

## 6. 排查 production bundle 的正确姿势（反 grep 中文）

黑屏排查时，我一度以为 PricingPanel 没进 bundle，因为：

```bash
grep -c "全局成本倍率" index-*.js   # = 0  ← 吓我一跳
grep -c "返回首页" index-*.js       # = 0
```

**这是误报**。两个原因：
1. `staticI18nPlugin` 把模板中文改写成 `{{ $ls(hash, "中文") }}`，源串虽在，但被包在调用参数里，普通 `grep -c` 在某些编码下假阴性
2. Windows 的 grep 对部分 UTF-8 中文有编码处理差异

**正确做法**——用**纯 ASCII 的标识符**反查，这些不会被 i18n 改写：

```bash
# 1. Call.ByName 的服务方法名（ASCII，稳定）
grep -abo "GetPricingSnapshot" frontend/dist/assets/index-*.js   # 有 offset = 组件在
grep -abo "SetDefaultCostMultiplier" frontend/dist/assets/index-*.js

# 2. 组件独有的 JS 标识符（minified 后变量名变，但属性名/字符串常量不变）
grep -abo "cacheWritePerMillion" frontend/dist/assets/index-*.js  # PricingPanel 表单字段

# 3. 用 hash 反查中文字串
node -e 'const{createHash:h}=require("crypto");
  console.log(h("sha256").update("全局成本倍率").digest("hex").slice(0,16))'
# → 2e945d5b50c837fe
grep -abo "2e945d5b50c837fe" frontend/dist/assets/index-*.js     # 有 offset = 字串在 bundle

# 4. locale 是否写入（--scan 是否跑过）
grep "2e945d5b50c837fe" frontend/src/i18n/locales/zh-CN.json     # 有 = 写了

# 5. 直接 dd 看 offset 附近字节，肉眼判断是 render function 还是 string table
dd if=frontend/dist/assets/index-*.js bs=1 skip=<offset> count=400 2>/dev/null
```

还有一个反直觉点：`Call.ByName(\`${SERVICE}.GetPricingSnapshot\`)` 这种模板字面量，minify 后 `${SERVICE}` 被内联成常量、整体拼成纯字符串，但**分隔方式**可能让 `grep "MetricsService.GetPricingSnapshot"` 返回 0，而 `grep "GetPricingSnapshot"` 返回 1。**以纯 ASCII 子串为准**，别用拼接后的全名查。

> **方法论**：验证构建产物时，**选不会被任何构建期变换触碰的 ASCII 标识符**作为探针。中文字串在有 i18n 插件的项目里不可靠。

## 7. 下次遇到“路由点进去黑屏”的标准排查顺序

1. **先让错误可见**：确认 `main.js` 的 showErrorOverlay 在、DevTools 开着。黑屏但有红字 vs 纯黑无信息，排查难度差 10 倍。
2. **看报错栈顶**：`String(<anonymous>)` → 多半是某处插值/序列化拿了个怪对象；`Cannot read properties of undefined` → 多半是数据未加载就渲染。
3. **定位偏移量**：报错里的 `9633:30` 指向 bundle 行列，配合 sourcemap 或直接 dd 那段字节，能看出是哪个组件的哪个表达式。
4. **比对差异**：为什么只有这个路由崩？对比正常路由和崩路由的 `meta`、组件 props、初始数据，找特异点。
5. **怀疑构建期变换**：本项目有 `staticI18nPlugin`、有 `LocalizedText extends String`，这俩是“看起来无害实则致命”的高危组合。任何把对象塞进 `{{ }}` 的路径都要审。
6. **改完走完整构建链**：`--scan` build → `generate syso` → `go build`，三步缺一会让你测到旧前端。

---

## 8. 一句话总结

> 黑屏 = 渲染期异常被坏掉的 errorHandler 吞掉 → 根因是 i18n 插件递归包装中文串，让路由 title 变成嵌套 LocalizedText 对象，`toDisplayString` 调 `String()` 命中 `Symbol.toPrimitive` 返回对象而崩。修 = 路由用裸串不嵌套 + 插值点 String() 兜底 + 错误浮层无条件可见 + 跑 --scan 把 hash 写进 locale。
