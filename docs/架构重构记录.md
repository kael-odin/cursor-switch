# 真实账号透传 + byok 模型路由分离（架构重构记录）

> 日期：2026-07-23 ~ 2026-07-24
> 版本：0.0.41 → 1.0.0
> 配套：`接口与架构速查.md`（接口分类速查）、`RELEASE_SIGNING.md`（发版签名）

## 背景

旧版 byok 通过**伪造 Ultra 假账号**（写入真实 `state.vscdb` + mock 全套 auth/dashboard/statsig）来解锁模型与 agent window。问题：

- 覆盖用户真实 Cursor 登录态，导致开着 byok 无法登录/退出真实账号
- marketplace/customize 是 mock 的假数据，能看不能装（`InstallUserPlugin` 等接口 404）
- 假 Ultra 与真实账号混用，UI 状态不一致

用户诉求：**开着 byok 用自定义模型的同时，能用真实 Cursor 账号的 marketplace/customize 全功能**。

## 核心决策：三条控制面分离

把 Cursor 的请求分成三条互不干扰的面，各有独立处理方式：

| 控制面 | 处理 | 凭证 | 目的 |
|---|---|---|---|
| **身份/marketplace/auth 登录** | 官方透传 `CredentialOriginalCursor` | 真实 Cursor 登录态 | 登录/退出/marketplace 浏览安装/customize 全功能 |
| **订阅/套餐/用量** | 本地 mock（无限制 Pro） | 无 | 解锁模型选择器，不被真实套餐 `allowedModelIds` 锁 auto |
| **模型推理/数据面** | byok 本地 | 用户配置的 provider key | 自定义模型路由 + 成本统计 |

**为何这样分**：byok 定位是"用你自己的 key/模型，不依赖 Cursor 套餐"。所以套餐权益必须 mock 成无限制（否则真实免费套餐会锁模型），但身份和 marketplace 必须真实（绑定账号）。

## 凭证链路（安全关键）

旧版用 HTTP `Authorization` 头同时承载"内部 loopback 信任"和"真实 Cursor 凭证"，导致后者被前者覆盖丢失。新版分离：

```
Cursor → MITM(internal/mitm/service.go forwardToServer)
       → 保留原始 Authorization/Cookie/x-cursor-checksum
       → 注入私有头 X-Cursor-BYOK-Relay-Proof（进程级随机，relayauth.New）
       → backend(internal/backend/server/middleware.go)
         → LoopbackAuth: 常量时间校验 proof，删除 proof 头
         → ServerContext: ParseUpstreamURL + CaptureAndStripCredentials
           → 捕获 Authorization/Cookie/checksum 到 ctx.Credentials
           → 从 request.Header 删除（本地 handler 不可见）
       → 路由 handler
         → 本地 mock：用不到凭证
         → CredentialOriginalCursor 出站：restoreOriginalCursorCredentials
           → 仅当目标=原始 HTTPS *.cursor.sh 且与 BoundTarget 一致才恢复
           → 否则 fail-closed（凭证保持剥离）
```

关键安全属性：
- 真实 Cursor 凭证只回原始 HTTPS `*.cursor.sh`，绝不发给第三方 provider 或 `tab.leokun.cn`
- 内部 proof 头永远不离开 backend 边界
- backend/proxy 强制只监听 loopback（`127.0.0.1`/`::1`）
- 不跟随重定向（`NewHTTPClientNoRedirect`），避免凭证随 3xx 外泄

## 调试历程与踩过的坑

### 坑 1：marketplace 面板转圈打不开
- **根因**：只 mock 了 `GetEffectiveUserPlugins`，但面板真正依赖 `ListMarketplaces`/`ListMarketplacePlugins`/`RegisterMarketplaceAndPlugins` 全部 404
- **教训**：加路由诊断日志（`route.dispatch method path name mode status`）定位精确的 404 接口
- **最终解**：marketplace 整条链改官方透传（不再 mock 假数据）

### 坑 2：安装插件 404
- **根因**：`InstallUserPlugin` 命中 catch-all 404。但逐个补接口是打地鼠（还有卸载/更新/MCP/Skills/Commands/Hooks）
- **解**：`DashboardService/*` catch-all 整体改官方透传，自动覆盖未来新增接口

### 坑 3：开着 byok 无法登录真实账号
- **根因**：`StartProxy` 每次无条件 `InjectCursorUserInfo` 把假 Ultra 写入真实 `state.vscdb`，Stop 不还原
- **解**：永久删除注入；新增 `RepairLegacyInjectedIdentity` 安全清理历史假值（仅完整旧假指纹匹配才删，绝不创建库/删真实值）

### 坑 4：`PreserveAuth` 没用
- **根因**：只阻止了 backend 第二次覆盖 Authorization，但 MITM 在更早的 `forwardToServer` 已经覆盖了
- **教训**：凭证覆盖发生在 MITM 边界，不在 backend。必须从 MITM 起就不覆盖
- **解**：改用独立 proof 头，Authorization 全程不动

### 坑 5：锁 auto（第一层）
- **根因**：`BootstrapStatsig` 本地 mock 注入 `free_user_model_picker`/`locked_picker` 实验，强制锁模型选择器
- **解**：statsig 改官方透传，由真实账号 gate 决定

### 坑 6：左下角账号名闪动
- **根因**：`GetMe` mock 假身份 vs `/auth/GetEmail` 透传真实邮箱，身份不一致
- **解**：`GetMe` 改官方透传（`GetMeResponse` 不含套餐字段，透传不触发锁 auto）

### 坑 7：锁 auto（第二层，某时刻瞬间切回）
- **根因**：`GetUsageLimitStatusAndActiveGrants`/`GetPlanInfo`/`GetCurrentPeriodUsage`/`IsOnNewPricing` 透传真实账号套餐，用 `allowedModelIds` 锁模型
- **解**：这 4 个套餐/定价/用量接口改回本地 mock（无限制 Pro）

### 坑 8：锁 auto（第三层，stripe 轮询风暴）
- **根因**：`full_stripe_profile`/`stripe_profile` 透传真实套餐，与本地 mock 的无限制用量**矛盾**，触发 Cursor 疯狂轮询 `stripe_profile`/`GetTeams`（每秒数十次），每次刷新重算模型选择器 → 锁 auto
- **关键洞察**：身份透传（真实）+ 套餐 mock（无限制）= 不一致。`GetMeResponse` 不含套餐字段，所以 `GetMe` 透传不矛盾；但 stripe 携带真实套餐，与用量 mock 矛盾
- **解**：stripe 三接口改回本地 mock，与套餐 mock 保持一致的"Pro + active + 付费有效 + 无限制"

## 最终分类原则（无矛盾版）

| 类别 | 接口 | 处理 | 矛盾点 |
|---|---|---|---|
| 身份 | `GetMe`/`GetEmail`/`GetUserProfile`/marketplace/auth 登录 | 透传 | 不矛盾（不含套餐字段） |
| 订阅/套餐/用量 | stripe×3 + PlanInfo + CurrentPeriodUsage + UsageLimitStatus + IsOnNewPricing | **全 mock 一致无限制 Pro** | 必须一致，否则轮询风暴 |
| statsig | BootstrapStatsig 等 | 透传 | 提供完整 Discover UI + 模型选择器行为 |
| 模型/数据面 | AvailableModels/GetDefaultModel/RunSSE/BidiAppend | byok 本地 | byok 模型路由不依赖 statsig |
