# 额外参数 JSON 与 自定义请求头 JSON 教学配置

模型适配器（ModelEditor）里有两组高级字段，大部分用户用不到，但某些 provider 场景必须配。本文给出**验证过的常用配置**和**不能配什么**，照抄即可。

> 字段位置：模型编辑器 → 「故障转移候选链」分组的下方，开关 + JSON 输入框。

---

## 一、额外参数 JSON（OpenAI / Anthropic）

### 它是什么

开启后，这个 JSON 对象会被**浅合并进发给 provider 的请求体**（同名字段以这里为准，会覆盖适配器自动生成的值）。两个独立字段：

- **额外参数 JSON**（`openAIExtraParamsJSON`）：合并进 OpenAI 兼容协议请求体（`/v1/chat/completions`、`/v1/responses`）。对走 OpenAI 兼容路由的 DeepSeek / Gemini / Grok / Kimi / Qwen / GLM / 小米 MiMo 等所有第三方中转都生效。
- **Anthropic 额外参数 JSON**（`anthropicExtraParamsJSON`）：仅当 type=anthropic 时可用，合并进 Anthropic 协议请求体（`/v1/messages`）。

### ⛔ 不能配的字段（会被静默丢弃 + 记日志）

下列字段由适配器按协议/路由自动设置，**你在 JSON 里写了也会被忽略**，防止破坏流控、绕过路由记账或伪造空流成功：

| 禁止字段 | 原因 |
|---|---|
| `stream` | 流开关，改 false 可能伪造空流成功 |
| `model` | 模型路由/记账字段，会绕过路由决策 |
| `messages` | Chat Completions 对话主体 |
| `input` | Responses API 对话主体 |
| `tools` | 工具定义 |
| `tool_choice` | 强制工具调用 |
| `system` | Anthropic 系统提示 |
| `instructions` | Responses API 系统提示 |
| `metadata` | 追踪元数据（user_id 等） |

### ✅ 验证过的常用配置

#### 1. OpenAI service_tier（优先级 / 弹性容量）

OpenAI 官方 API 的服务层级，影响排队优先级和计费。默认 JSON 就是这个：

```json
{
  "service_tier": "priority"
}
```

可选值：`auto` / `default` / `flex`（弹性，更便宜但高峰可能排队）/ `scale` / `priority`（最高优先级）。

> 仅对 **OpenAI 官方 API** 有效。第三方中转（DeepSeek/Kimi 等）传了通常被忽略，无副作用。

#### 2. 自定义 prompt 缓存前缀（Anthropic）

想强制某个固定系统段被缓存以省 token，可加 `cache_control`（注意：直接合并进顶层 body，Anthropic 的缓存控制本就在 message 块里，这里只给能放顶层的字段示例）：

```json
{
  "top_p": 0.95,
  "temperature": 0.7
}
```

> 采样参数 `temperature` / `top_p` / `top_k` / `max_tokens` 等都是合法的额外参数，可按需配。

#### 3. 关闭/调小 thinking（部分中转）

某些走 Anthropic 兼容路由的中转支持 `thinking` 字段（注意 cursor-switch 已内置 thinking signature 整流器处理无效签名，一般不用你手配）：

```json
{
  "thinking": {
    "type": "disabled"
  }
}
```

> Cursor 客户端已通过适配器的 `reasoningEffort` / `anthropicThinkingEffort` 字段控制思考强度，通常无需在额外参数里再配 thinking——除非你要强制覆盖。

### 怎么验证配对了

保存后看 `~/.cursor-local-assistant-v2/logs/app.log`，grep `modeladapter`：被 blocked 的字段会打 `extra param "xxx" blocked`；正常合并不报错。

## 二、自定义请求头 JSON

### 它是什么

开启后，这个 JSON 对象的每个键值会被**设置到发给 provider 的 HTTP 请求头**上（同名以这里为准，覆盖适配器自动生成的值）。**值必须是字符串**（数字/布尔会被校验拒绝）。

### ⛔ 不能配的请求头（会被静默丢弃 + 记日志）

这些头由适配器按 provider 协议设置真实凭据/路由，**允许覆盖会把鉴权重定向到攻击者端点**，故一律禁止：

| 禁止头 | 原因 |
|---|---|
| `Authorization` | Bearer token 鉴权头，由 apiKey 生成 |
| `x-api-key` | Anthropic 风格鉴权头，由 apiKey 生成 |
| `Host` | 路由目标，由 baseURL 决定 |
| `Cookie` | 会话凭证，防泄漏 |

> 大小写不敏感（`authorization` 和 `Authorization` 都会被 block）。

### ✅ 验证过的常用配置

#### 1. 第三方中转要求带自定义识别头

很多中转商（非官方 OpenAI/Anthropic）要求你在 API Key 之外额外带一个渠道标识或项目头：

```json
{
  "X-Channel-Id": "my-channel-123",
  "X-Project": "cursor-byok"
}
```

#### 2. 经 Cloudflare / 反代加路径标识

```json
{
  "CF-Access-Client-Id": "xxx.access",
  "CF-Access-Client-Secret": "yyy.access"
}
```

#### 3. 指定 API 版本（部分 provider）

```json
{
  "X-API-Version": "2026-01-01"
}
```

> 值必须是字符串——`"X-Timeout": 30` 会被校验拒绝，写成 `"X-Timeout": "30"` 才行。

### 怎么验证配对了

同样看 `app.log`，grep `custom header`：被 block 的会打 `custom header "xxx" blocked (would override auth/host)`。

---

## 三、和「获取模型列表」的关系

点「获取模型列表」时，会用当前编辑器里填的 baseURL/apiKey/endpoint/**customHeaders** 去调 provider 的 `/v1/models`。所以如果中转要求自定义头才能拉模型列表，**先填好自定义请求头 JSON 再点获取**。

---

## 四、常见误区

1. **「值必须是字符串」**：自定义请求头里 `{"X-Num": 1}` 会报错，写 `{"X-Num": "1"}`。
2. **想改模型/流/消息**：这些是协议核心字段，不能通过额外参数覆盖——它们的值由你选的模型、Cursor 客户端的请求、路由决策共同决定。
3. **想覆盖 Authorization 换个 key**：用「故障转移候选链」配多个 adapter（同 modelID 不同 apiKey + Priority），而不是在请求头里塞 Authorization——后者被 block。
4. **额外参数对第三方中转无效还报错**：部分中转会原样校验请求体，传了它不认识的字段（如给 DeepSeek 传 `service_tier`）可能 400。此时关掉额外参数开关即可（默认 OpenAI 额外参数填了 `service_tier` 但开关默认关，不影响）。
