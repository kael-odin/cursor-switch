# cursor-byok 接口与架构速查（真实账号透传 + byok 模型路由分离）

> 维护：每次改路由/凭证策略后更新本文档。配套 `cursor-byok-marketplace解锁实施记录.md`（按批次记改动历程）。
> 核心原则：**身份/marketplace/auth 走官方透传（真实 Cursor 账号），套餐/定价/用量类走本地 mock（无限制解锁模型），模型推理/数据面走 byok 本地。**

## 一、三条控制面（架构核心）

byok 把 Cursor 的请求分成三条互不干扰的面：

| 控制面 | 处理方式 | 凭证 | 目的 |
|---|---|---|---|
| **身份/marketplace/auth** | 官方透传 `CredentialOriginalCursor` | 真实 Cursor 登录态 | 登录/退出/marketplace 浏览安装/customize 全功能 |
| **套餐/定价/用量** | 本地 mock（无限制） | 无 | 解锁模型选择器，不被真实套餐 `allowedModelIds` 锁 auto |
| **模型推理/数据面** | byok 本地 | 用户配置的 provider key | 自定义模型路由 + 成本统计 |

**为何这样分**：byok 定位是"用你自己的 key/模型，不依赖 Cursor 套餐"。所以套餐权益必须 mock 成无限制（否则真实免费套餐会锁模型），但身份和 marketplace 必须真实（绑定账号）。

## 二、凭证链路（安全关键）

```
Cursor → MITM(internal/mitm/service.go forwardToServer)
       → 保留原始 Authorization/Cookie/x-cursor-checksum
       → 注入私有头 X-Cursor-BYOK-Relay-Proof（进程级随机，relayauth.New）
       → backend(internal/backend/server/middleware.go)
         → LoopbackAuth: 常量时间校验 proof，删除 proof 头
         → ServerContext: ParseUpstreamURL + CaptureAndStripCredentials
           → 捕获 Authorization/Cookie/checksum 到 ctx.Credentials
           → 从 request.Header 删除（本地 handler 不可见）
       → 路由 handler
         → 本地 mock：用不到凭证
         → CredentialOriginalCursor 出站：restoreOriginalCursorCredentials
           → 仅当目标=原始 HTTPS *.cursor.sh 且与 BoundTarget 一致才恢复
           → 否则 fail-closed（凭证保持剥离）
```

**关键文件**：
- `internal/relayauth/proof.go` — 进程级 proof（`HeaderRelayProof`=`X-Cursor-BYOK-Relay-Proof`）
- `internal/mitm/service.go:forwardToServer` — 不再覆盖 Authorization，注入 proof
- `internal/backend/server/context.go:CaptureAndStripCredentials` — 捕获+剥离
- `internal/backend/server/upstream/client.go:restoreOriginalCursorCredentials` — 目标校验后恢复
- `internal/backend/server/upstream/client.go:scrubReservedHeaders` — 默认剥离所有敏感头

> 身份接口（GetMe/GetEmail）透传不矛盾——GetMeResponse 不含套餐字段。

## 四、helper（host.go）

- `officialProcedure(pattern, name, protocol, deps)` — POST 官方透传（`CredentialOriginalCursor`）
- `officialAnyProcedure(pattern, name, protocol, deps)` — Any 方法官方透传
- `directUpstreamProcedure` — POST 透传到 `api2.cursor.sh:443`（旧式）
- `tabServerUpstreamProcedure` — 转发到 `tab.leokun.cn`（`CredentialNone`）
- `repositoryServiceProcedure`/`uploadServiceProcedure` — 本地 forwarder

## 五、本地身份注入（已移除）

- `StartProxy` 不再调 `InjectCursorUserInfo`（不再覆盖真实 `state.vscdb`）
- `RepairLegacyInjectedIdentity`（`internal/cursor/state_db.go`）：首启清理历史假账号（仅完整旧假指纹匹配才删，绝不创建库/删真实值）
- `internal/runtime/defaults.go`：假身份常量 + loopback token 已删空

## 六、调试

- **日志**：`C:\Users\user\.cursor-local-assistant-v2\logs\app.log`，搜 `route.dispatch` 看每个请求的 `method/path/name/mode/status`
- **mode=local** = MITM 中继来的请求走 Local 分支（透传 or mock 都可能是 local）
- **status=404** = 命中 catch-all 但 handler 不认（如未显式 mock 的 AiService 方法）
- **锁 auto 排查**：确认 `GetUsageLimitStatusAndActiveGrants`/`IsOnNewPricing`/`GetPlanInfo`/`GetCurrentPeriodUsage` 都是本地 mock（非透传），`GetDefaultModel`/`AvailableModels` 是本地 mock 返回 byok 模型
- **闪动排查**：确认 `GetMe`/`full_stripe_profile` 走透传（真实身份一致）
- **marketplace 不全排查**：确认 `BootstrapStatsig` 走透传（真实 statsig gate）
