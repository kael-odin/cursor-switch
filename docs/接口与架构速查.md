# cursor-switch 接口与架构速查（真实账号透传 + byok 模型路由分离）

> 维护：每次改路由/凭证策略后更新本文档。配套 `cursor-switch-marketplace解锁实施记录.md`（按批次记改动历程）。
> 核心原则：**身份/marketplace/auth 走官方透传（真实 Cursor 账号），套餐/定价/用量类走本地 mock（无限制解锁模型），模型推理/数据面走 byok 本地。**

## 一、三条控制面（架构核心）

byok 把 Cursor 的请求分成三条互不干扰的面：

| 控制面 | 处理方式 | 凭证 | 目的 |
|---|---|---|---|
| **身份/marketplace/auth** | 官方透传 `CredentialOriginalCursor` | 真实 Cursor 登录态 | 登录/退出/marketplace 浏览安装/customize 全功能 |
| **套餐/定价/用量** | 本地 mock（无限制） | 无 | 解锁模型选择器，不被真实套餐 `allowedModelIds` 锁 auto |
| **模型推理/数据面** | byok 本地 | 用户配置的 provider key | 自定义模型路由 + 成本统计 |

**为何这样分**：byok 定位是"用你自己的 key/模型，不依赖 Cursor 套餐"。所以套餐权益必须 mock 成无限制（否则真实免费套餐会锁模型），但身份和 marketplace 必须真实（绑定账号）。

## 二、凭证链路（安全关键）

```
Cursor → MITM(internal/mitm/service.go forwardToServer)
       → 保留原始 Authorization/Cookie/x-cursor-checksum
       → 注入私有头 X-Cursor-BYOK-Relay-Proof（进程级随机，relayauth.New）
       → backend(internal/backend/server/middleware.go)
         → LoopbackAuth: 常量时间校验 proof，删除 proof 头
         → ServerContext: ParseUpstreamURL + CaptureAndStripCredentials
           → 捕获 Authorization/Cookie/checksum 到 ctx.Credentials
           → 从 request.Header 删除（本地 handler 不可见）
       → 路由 handler
         → 本地 mock：用不到凭证
         → CredentialOriginalCursor 出站：restoreOriginalCursorCredentials
           → 仅当目标=原始 HTTPS *.cursor.sh 且与 BoundTarget 一致才恢复
           → 否则 fail-closed（凭证保持剥离）
```

**关键文件**：
- `internal/relayauth/proof.go` — 进程级 proof（`HeaderRelayProof`=`X-Cursor-BYOK-Relay-Proof`）
- `internal/mitm/service.go:forwardToServer` — 不再覆盖 Authorization，注入 proof
- `internal/backend/server/context.go:CaptureAndStripCredentials` — 捕获+剥离
- `internal/backend/server/upstream/client.go:restoreOriginalCursorCredentials` — 目标校验后恢复
- `internal/backend/server/upstream/client.go:scrubReservedHeaders` — 默认剥离所有敏感头

## 七、成本定价（1.0.0+，照搬 cc-switch）

byok 的成本定价体系：**预设标准价目表 + 用户自定义 CRUD + 全局/per-adapter 倍率 + by_model 用量聚合**。

### 数据模型（config.yaml 的 `pricing` 段）

```yaml
pricing:
  defaultCostMultiplier: "1"        # 全局默认倍率（字符串保精度）
  models:                            # 模型定价表（USD/百万 token）
    - modelId: claude-opus-4-7
      displayName: Claude Opus 4.7
      inputPerMillion: "5"
      outputPerMillion: "25"
      cacheReadPerMillion: "0.50"
      cacheWritePerMillion: "6.25"
```

`ModelAdapterConfig.CostMultiplier`（可选）：per-adapter 倍率，覆盖全局默认。

### 内置预设价目表

`internal/backend/server/config/pricing.go` 的 `pricingModelSeed` 含 100+ 模型标准价（Claude/GPT/Gemini/Grok/DeepSeek/Kimi/Doubao/Qwen/GLM/MiniMax/MiMo 等），首次启动按 modelId 增量补齐（用户编辑过的不覆盖）。

### 成本计算公式

```
单模型成本 = (input_tokens/1M × input_price
           + output_tokens/1M × output_price
           + cache_read_tokens/1M × cache_read_price
           + cache_write_tokens/1M × cache_write_price) × multiplier
总成本 = Σ 单模型成本
```

倍率优先级：per-adapter `CostMultiplier` > 全局 `defaultCostMultiplier` > 1。

### by_model 用量聚合（usage.json）

`usage.json` 新增 `by_model` 段：每个 `provider_call` 事件携带 `model_id`/`model_name`，按模型聚合 token 用量。`turn_finalized` 事件从聚合继承模型归属。

## 九、i18n 嵌套陷阱与「定价管理黑屏」根因（重要，未来排查必读）

### 现象
点击首页「定价管理」→ 窗口纯黑、无法拖动，DevTools 报：
```
[vue] Cannot convert object to primitive value
TypeError: Cannot convert object to primitive value
  at String (<anonymous>)
  at z (assets/index-*.js:117:199)          ← Vue 运行时 toDisplayString（minified 名 z/x）
  at Proxy.<anonymous> (...:9633:30)        ← MainLayout header 的 {{ title }}
```

### 根因（两层）

**第一层：`staticI18nPlugin` 会递归包装中文串。**
`frontend/plugins/static-i18n-plugin.js` 的 `collectJSReplacements` 对所有含 Han 的 `StringLiteral` 一视同仁地包成 `localized(hash, source)`——**包括已有 `localized(hex, "中文")` 调用里的那个 `"中文"` 参数本身**。结果：
```js
// 源码写的：
title: localized("pricing_panel_title", "成本定价")
// 插件改写成（"成本定价" 也是 StringLiteral，被二次包装）：
title: localized("pricing_panel_title", localized("82c5adb194b84b77", "成本定价"))
```
外层 `localized` 的 fallback 变成了一个 **LocalizedText 对象**，而不是原始字符串。

**第二层：`LocalizedText` 的 `toString()` 在 hash 未命中时会返回对象。**
`frontend/src/i18n/runtime.js` 的 `LocalizedText extends String`，其 `toString/valueOf/Symbol.toPrimitive` 都返回 `resolveMessage(id, fallback)` 的结果：
```js
resolveMessage(id, fallback) = activeMessages[id] || sourceMessages[id] || fallback || ""
```
当 `id`（如 `pricing_panel_title`）**不是真正的 locale key** 时，前两步都 miss，直接返回 `fallback`——而这里 fallback 是个 LocalizedText **对象**。Vue 的 `toDisplayString` 最终会调 `String(value)`，命中 `Symbol.toPrimitive`，拿到对象 → 抛 `Cannot convert object to primitive value`。

**安全条件**：只要外层 `localized` 的 hash key 真的存在于 locale JSON，`resolveMessage` 第一步就返回字符串，永远走不到 fallback，对象就不会暴露。所以只有「hash 未命中 + fallback 又被嵌套包装」两者同时成立时才崩。`pricing_panel_title` 是我手写的伪 key，locale 里没有，于是踩雷。

### 修复（已应用）
1. **`frontend/src/router/index.js`**：`/pricing` 路由的 `meta.title` 改成裸字符串 `"成本定价"`，不再写 `localized("pricing_panel_title", localized(...))` 这种嵌套形式。插件仍会把它包成 `localized("82c5adb194b84b77", "成本定价")`——这是**单层**，安全（fallback 是原始字符串）。
   - 规则：`meta.title` 只接受原始字符串或单层 `localized(hex, "中文")`，**切勿嵌套**。
2. **`frontend/src/layouts/MainLayout.vue`**：`title` computed 加 `String(raw)` + `try/catch` 兜底，即便将来再出现嵌套对象也不会让整个 header 崩掉。
3. **`frontend/src/main.js`**：原有 `app.config.errorHandler` 只在 `#root` 无子节点时写 DOM——但崩在半渲染态时 root 已有半个子树，错误被吞 → 纯黑。新增**无条件** `showErrorOverlay`（固定全屏 `#__err_overlay`）+ `window.error`/`unhandledrejection` 监听，保证任何渲染期异常都可见、可复制。

### 如何验证 production bundle（排查黑屏必备）
黑屏排查时**不能 grep 中文**——`staticI18nPlugin` 把模板里的中文改写成 `{{ $ls(hash, "中文") }}`，源串虽在但被包在调用里，且 Windows grep 对部分中文有 UTF-8 假阴性。正确做法：

```bash
# 1. 用 ASCII 的 Call.ByName 串定位组件是否进 bundle（不会被 i18n 改写）
grep -abo "GetPricingSnapshot" frontend/dist/assets/index-*.js   # 应有 offset
grep -abo "SetDefaultCostMultiplier" frontend/dist/assets/index-*.js
# 2. 用 hash 反查组件的中文字串是否进 bundle + locale
node -e 'const{createHash:h}=require("crypto");console.log(h("sha256").update("全局成本倍率").digest("hex").slice(0,16))'
grep -abo "<hash>" frontend/dist/assets/index-*.js                # 应出现在代码段 + 三份 locale
grep "<hash>" frontend/src/i18n/locales/zh-CN.json                # --scan 后必写入
# 3. 直接 dd 看 offset 附近字节，确认是 render function 还是 string table
dd if=frontend/dist/assets/index-*.js bs=1 skip=<offset> count=400 2>/dev/null
```

`MetricsService.Xxx` 这类模板字面量在 minify 后会被拆开（`${fo}.GetPricingSnapshot` 里的 `fo` 是被替的常量），所以 `grep "MetricsService.GetPricingSnapshot"` 可能 0 命中但组件其实在——以 `GetPricingSnapshot` 这种纯 ASCII 子串为准。

### syso 是前端资源的载体
`wails_windows_amd64.syso` 把 `frontend/dist/**` 嵌进 exe。**改前端后必须重跑 `wails3 generate syso` 再 `go build`**，否则 exe 里仍是旧前端。syso 文件 mtime 早于 `frontend/dist` 即陈旧。生成命令见 `build/windows/Taskfile.yml:generate:syso`。
